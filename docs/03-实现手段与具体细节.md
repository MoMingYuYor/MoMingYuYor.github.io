# 个人主页实现手段与具体细节

日期：2026 年 9 月 19 日。本文件规定个人主页首版的实现边界和可验收行为，供后续开发直接使用。页面采用沉浸式山湖全幅壁纸首屏，向下接兴趣画廊、项目画廊和关于区；深色与浅色模式拥有同等完整的内容、布局与操作。个人身份资料和正式照片尚待提供，页面当前使用标注为演示的内容与占位图运行，正式发布前逐项核验。

## Goal

首屏以山湖照片建立空间感，清晰呈现姓名占位、简短介绍和进入内容的入口。完整内容具备 `home`、`interests`、`projects`、`about` 四个锚点；当兴趣或项目没有可展示条目时，对应章节和导航入口一同省略，实际可见章节编号连续生成。兴趣与项目各有独立章节，避免将私人爱好和作品经历混作同一组内容。移动端根据内容自然延伸；桌面端可以在确认不妨碍阅读、键盘导航和锚点定位后加入 `scroll-snap-type: y proximity`，绝不截获滚轮或强行锁定单屏。

首版仅处理静态文本、照片以及有资源时由用户主动播放的可选音频。日期若展示，只按设备本地日期格式化，不由此推断所在地或时区。不接入天气或其他第三方 API，不做账户、后台、留言、数据库和数据分析。项目发布地址与源码地址均可缺省，缺省时不渲染对应操作，也不填入看似真实的假地址。

## Architecture

采用 Vue 3、TypeScript、Vite 和原生 CSS，构建结果为可部署的静态 `dist`。首版无需 Router、Pinia、大型 UI 库或 GSAP；页面状态仅包括主题偏好与两个画廊各自的激活项，组件内部或 composable 足以管理。使用 npm 与 `package-lock.json`；依赖具体版本应在开发启动时查询、确定并锁定，本规范不臆造版本号。

`src/App.vue` 装配 `Header`、`Hero`、`InterestGallery`、`ProjectGallery`、`AboutSection`、`Footer` 和 `ThemeSwitch`。两处画廊在视觉内容上独立，但可共享一个 `GallerySection.vue` 的键盘、标签和图片状态逻辑；`InterestGallery` 与 `ProjectGallery` 只负责传入各自数据和文案，不再增加与首版无关的状态层。站点内容集中于 `src/content/site.ts`，字段类型放在 `src/types/content.ts`，内容纯逻辑校验放在 `src/content/validate.ts`。主题偏好的纯逻辑位于 `src/lib/theme.ts`，浏览器事件与生命周期位于 `src/composables/useTheme.ts`；主题变量写入 `src/styles/tokens.css`，全局排版和基础交互写入 `src/styles/global.css`，各组件保留局部样式。

## Tech Stack 与内容契约

以下 schema 给出首版所需的最小形状。`status: 'demo'` 是显式演示标记，不代表任何真实个人身份；原型使用独立的示意图片，不把含页面文字的整张概念稿当作壁纸。正式素材更新时沿用相同字段。内容图跨主题保持原图和说明，主题切换只选择首屏壁纸并调整配色，不替换项目截图或重排数据。

```ts
// src/types/content.ts
export type Theme = 'light' | 'dark'
export type ThemePreference = 'system' | Theme

export interface ImageAsset {
  src: string
  alt: string
  width: number
  height: number
  kind: 'photo' | 'screenshot'
  mobileSrc?: string
  desktopPosition?: string
  mobilePosition?: string
  candidates?: { src: string; width: number }[]
  sizes?: string
}

export interface GalleryItem {
  id: string
  title: string
  summary: string
  image: ImageAsset
  publishedUrl?: string
  sourceUrl?: string
}

export interface ProjectItem extends GalleryItem {
  role: string
  period: string
  background: string
  outcome: string
}

export interface ContactLink { label: string; href: string }

export interface SiteContent {
  status: 'demo' | 'ready'
  identity: {
    displayName: string
    headline: string
    introduction: string
    avatar?: ImageAsset
  }
  seo: {
    title: string
    description: string
    locale: 'zh-CN'
    canonicalUrl?: string
    shareImage?: ImageAsset
    allowIndex: boolean
  }
  hero: { dark: ImageAsset; light: ImageAsset }
  interests: GalleryItem[]
  projects: ProjectItem[]
  about: { heading: string; paragraphs: string[]; photo?: ImageAsset }
  contacts: ContactLink[]
  audio?: { src: string; title: string }
}
```

上例 `images/*.webp` 是未来开发时的资源路径示意，当前不存在，不能把它当作已就绪图片。路径保留为不带开头斜杠的站点资源键，由统一资源路径函数结合 Vite `base` 转成部署地址；GitHub Pages 等子路径部署不能硬编码 `/images`。视觉方向可参考本地概念稿：[深色首屏](assets/home-dark-concept.png)与[浅色首屏](assets/home-light-concept.png)，但整张含示意文字的概念稿不得直接用作网页壁纸。实施时应从获得使用许可的最终照片导出适配尺寸的 AVIF/WebP 与兼容备用格式，保留自然比例并在 `width`、`height` 中写实际像素。首版画廊以有主图的条目为可展示条目；只有项目说明而没有主图时，资料仍可暂存于编辑清单，但不进入 `site.projects`。`status: 'demo'` 时允许显式标注的演示条目帮助开发；数组为空则隐藏相应章节与导航项，不生成空 tablist。`contacts` 为空时隐藏联系入口。

内容校验是开发和构建时的明确关口。`validateSiteContent(site)` 返回可定位到字段路径的错误列表，由构建前检查脚本在错误非空时退出失败；它是无 DOM、无网络、无存储副作用的纯函数。应检查合法 `status`、名称和介绍非空、两张首屏图及全部可展示条目的有效 `src`、合法图片 `kind`、正整数尺寸、条目标题和简介、`id` 在所在画廊中唯一、项目角色/时间/背景/成果、可选链接与联系地址的合法协议，以及音频标题和路径。项目发布与源码链接只接受 `https:` 或明确允许的站内相对地址，联系方式还可接受 `mailto:`；空格和 `#` 均无效。首屏壁纸是装饰图，`alt=""`，姓名与说明文字由页面本身朗读；有信息的内容图与可选关于照片必须有非空替代文本。照片可裁切，截图用 `object-fit: contain` 保全边缘。空画廊是合法配置且整章隐藏，含条目的画廊则完整校验。`ready` 状态还须由人工逐项核验真实姓名或获授权展示名、介绍、正式媒体与链接，校验脚本不能仅凭状态值自动断定内容真实。

## 主题、首屏与样式

资源地址统一由计划文件 `src/lib/assets.ts` 中的 `assetUrl(path, base)` 处理：内部素材使用不含前导斜杠的资源键，结合 `import.meta.env.BASE_URL` 生成地址；拒绝协议相对地址与 `..` 目录穿越。远程图片仅接受已核验的 HTTPS 地址。`candidates` 中每个地址先完成 base 处理，再序列化为 `srcset`，不要给整段 srcset 添加路径前缀。`mobileSrc` 缺省时使用同主题主图，裁切位置缺省时使用 `50% 50%`。本地文件是否存在由构建准备脚本检查，纯内容校验只检查字段与路径语义。

App 只建立一个主题控制实例并向子组件传递，避免重复监听。快速连续切换时，为图片加载任务递增序号，只有最后一次请求可以提交画面。文字与界面色值立即切换，待图期间用遮罩或纯色回退保证可读性，不能让旧主题照片与新主题文字形成短暂低对比。

主题偏好只有 `system`、`light`、`dark` 三种；实际显示主题 `effectiveTheme` 只有 `light`、`dark`。首次访问默认 `system`，优先读取 `localStorage` 键 `personal-home:theme`；值不在枚举中或读取被阻止时退回 `system`。写入失败只影响跨会话持久化，当前会话继续保持用户刚选的主题。`src/lib/theme.ts` 提供偏好解析和 `resolveTheme(preference, systemIsDark)` 等纯函数；`useTheme.ts` 持有响应状态、执行持久化、监听 `matchMedia('(prefers-color-scheme: dark)')` 的 `change`，并在组件卸载时移除监听。系统外观变化只在偏好为 `system` 时改变有效主题。用户选择主题后只更新根元素 `data-theme`、`color-scheme` 和相关响应图片，不能重建 App、重置画廊激活项、焦点或滚动位置。

为避免首屏先亮后暗或相反，`index.html` 在 CSS 加载前放一段极小的内联引导脚本，使用同一存储键和枚举规则计算有效主题，立即设置 `document.documentElement.dataset.theme`。脚本只执行主题初始化，不读取身份信息或注入页面内容，并对禁用存储、缺少 `matchMedia` 作安全降级。Vue 挂载后 composable 复用相同规则接管，避免两套判定漂移。CSS 默认变量定义浅色兜底，`data-theme="dark"` 覆盖暗色；无 JavaScript 时系统媒体查询仍能给备用说明提供合理配色。主题切换控件应有可理解的 `aria-label`，明确当前选择与“跟随系统”选项，不能只靠太阳/月亮图标传达状态。

设计变量的基准为深色背景 `#15191d`、正文 `#f2eee6`、次级字 `#b2b9bf`、点缀 `#d2ad72`；浅色背景 `#f7f5f0`、正文 `#242a2c`、次级字 `#646967`、点缀 `#875b2d`。深浅边框分别取 `#39434d` 与 `#d8d5cf`，玻璃底色分别取 `rgba(18,30,44,.72)` 与 `rgba(255,253,247,.82)`，实际叠加到照片上时仍须测量对比度。首屏照片铺满可见区域但不能因固定高度裁掉内容：桌面可用 `min-height: 100svh`，低视口和移动端允许内容撑开；图片 `object-fit: cover` 并按画面主体配置 `object-position`。文字与照片之间用独立遮罩层提供局部深浅渐变，必要时使用半透明底板，确保普通字至少 4.5:1、大字至少 3:1。遮罩与文字层的层级应固定，点击目标不被遮罩拦截。

首屏用单个 `<picture>`，根据有效主题绑定一组壁纸资源，`mobileSrc` 作为窄屏 source，`src` 为桌面图及 `<img>` 兜底；`desktopPosition`、`mobilePosition` 控制不同裁切焦点。只创建当前主题的图片节点，避免 CSS 隐藏的另一张全幅图仍被下载；主题切换时预载目标图并在加载完成后换图，失败则保留主题色渐变背景。图片尺寸与 `aspect-ratio` 预留空间，首屏主图使用适当 `fetchpriority="high"`，下方图库图片懒加载并采用异步解码。桌面初始主图目标预算不超过 350 KB、移动端不超过 180 KB，这是设计预算，须用实际素材质量和网络测试复核。640 px 和 1024 px 作为主要响应断点，在 1440、1024、768、390、320 px 宽检查文字行长、遮罩覆盖、点击目标和内容溢出；390×844 等典型移动视口不强求一屏装完。

## 画廊、导航与媒体交互

图库状态纯逻辑统一放在 `src/lib/gallery.ts`。生成 DOM id 时使用章节前缀与条目 id 的组合，避免兴趣与项目中的同名条目冲突。无链接的内容面板自身使用 `tabindex="0"` 以便键盘进入阅读。图片尚未加载时立即呈现标题和说明，不因下载延迟阻塞标签激活。若增加悬停预览，仅用于支持精细指针的设备且不移动键盘焦点。

纯 SPA 首次挂载前锚点目标尚不存在，挂载完成后检查 `location.hash`，目标存在时定位一次，不额外写入历史；目标因空数据被省略时保留当前安全位置。手机菜单采用普通展开导航，按钮维护 `aria-expanded` 与 `aria-controls`；Escape 关闭并返回按钮，选择锚点后关闭菜单并把焦点移至对应标题，不把焦点留在已隐藏菜单中。

两个画廊各自维护 `activeId`。采用 tabs 模式：容器为 `role="tablist"`，每个标签为按钮且有稳定 `id`、`role="tab"`、`aria-selected`、`aria-controls` 和受控 `tabindex`；对应 `role="tabpanel"` 使用 `aria-labelledby`，任一时刻只显示激活面板。桌面侧栏为竖向标签栏，设置 `aria-orientation="vertical"`，上/下方向键移动并激活相邻项；移动端若改为横向条目列，移除竖向声明，左/右方向键承担同一操作。`Home` 到首项，`End` 到末项，边界循环行为在两种布局中一致。触屏点击直接选择，Tab 键从激活标签进入面板中的链接，隐藏面板元素不可获得焦点。若图册为空，整章与导航项省略；若仅有一项，保留内容但可省略标签栏和方向导航；若数据更新删除当前项，优先选原位置的下一项，末尾则选前一项，最后为空则清除 `activeId`。`activeId` 回退由纯函数实现，避免两个画廊各自复制边界逻辑。

首版是纯 Vue SPA，禁用 JavaScript 时 Vue 组件不会渲染，因此不承诺无脚本浏览完整画廊。`index.html` 在 `#app` 外提供最小静态 `<noscript>` 说明，告知需要 JavaScript 浏览完整主页，并在已确认可公开的联系地址存在时提供一个真实联系入口；演示阶段或联系方式缺失时只显示说明。该地址作为发布构建时的静态注入值，与 `site.contacts` 一同核验，避免手工维护两套不同地址。若未来要求无脚本阅读所有章节，须增加预渲染及其独立验收，不纳入本首版。

顶部锚点使用原生 `<a href="#…">`，目标章节有对应 `id` 和 `scroll-margin-top`，避开固定 Header；隐藏章节没有导航项，也不以 `replaceState` 覆写访问记录。当前章节提示可以通过 `IntersectionObserver` 增强，但不得成为跳转的前提；浏览器历史、深链接与键盘激活应保持原生行为。移动端不设置强制吸附。所有滚动、切换、淡入动画受 `prefers-reduced-motion: reduce` 控制，减少动画时直接显示最终状态、取消平滑滚动；键盘焦点始终有可见轮廓。

若 `audio` 缺省，音频入口完全隐藏。若提供资源，控件显示曲名、播放/暂停和可访问状态，只在明确点击或键盘激活后调用 `play()`；拒播、加载失败或文件不可用时保留页面功能并提示可恢复的错误，不自动循环或播放。离开页面及组件销毁时暂停并释放事件监听。可以使用浏览器原生 `<audio controls>` 作为可靠首选，视觉定制不应遮蔽其可访问操作。

图片请求失败时，`Hero` 保留纯色渐变背景、原有文字与导航；内容图维持已预留的比例框，显示简短替代文案或占位图，且记录非敏感开发错误。单张图失败不能使整页崩溃。Vue 的异步交互错误、被拒绝的媒体 Promise 和意外内容配置错误应在各自边界处理：构建阶段拒绝结构错误，运行阶段以稳定的静态内容或局部降级保留主要信息。避免把内部堆栈直接展示给访客。

## SEO、验收与开发顺序

元数据输入统一来自 `site.seo`；只有 `status === 'ready' && seo.allowIndex === true` 才生成允许索引的标记，`demo + allowIndex` 组合直接报错。`canonicalUrl` 若存在必须是最终站点 HTTPS 地址，分享图在地址确定后转为绝对 URL。元数据对象由 `prepare-site.ts` 生成至构建中间文件，再由 `vite.config.ts` 的 `transformIndexHtml` 注入受版本管理的 HTML 模板；开发服务器同样执行准备流程，不在源码 HTML 中累积写入旧内容。`noindex` 不是访问控制，未公开资料不得仅凭这一标签上传。`seo.title`、`description`、`locale`、身份 headline、可选头像和分享图也需纳入结构校验。

草稿站设置 `noindex, nofollow`，并在托管侧避免被公开索引。`scripts/prepare-site.ts` 在构建前读取 `site`、运行内容校验，再生成 `index.html` 所需的转义后标题、描述、语言、分享图、规范地址和最小无脚本联系入口；草稿缺少真实身份或域名时省略分享图与规范地址，不写假值。构建注入必须对 HTML 属性和文本转义，静态联系入口仅使用已核验的公开地址。发布前将演示身份、概念图、替代文字、媒体授权、可选链接与 `status` 逐项复核，再移除草稿索引限制。单页静态输出的路由需求仅为锚点，不增加 history fallback 配置。

开发顺序从内容与构建元数据开始，随后实现主题与样式，再装配首屏、章节与画廊，最后完成媒体降级和访问检查。`package.json` 预定提供 `dev`、`build`、`preview`、`typecheck`、`test:unit`、`test:e2e` 与 `check:content` 脚本；`build` 必须先执行内容准备再调用 Vite，具体命令在依赖确定后写入并与锁文件一起提交。下表是开发时的任务、文件和最小验收对应关系。

任务表中未带目录的 Vue 组件均位于 `src/components/`；资源路径函数位于 `src/lib/assets.ts`，图库状态函数位于 `src/lib/gallery.ts`，构建注入由 `vite.config.ts` 配合准备脚本完成。初次初始化先安装核定的依赖并生成锁文件；下面的 `npm ci` 适用于锁文件已存在的后续干净安装。所有命令均为未来验收计划，当前未执行：

```sh
npm run check:content
npm run typecheck
npm run test:unit
npm run build
npm run test:e2e
```

Vitest 重点验证偏好解析、系统切换、无效存储值降级、内容校验和 active 项被删除后的回退纯函数。Playwright 覆盖深浅两模式首屏与后续章节截图、竖向及横向 tabs 键盘导航、触屏点击、锚点深链接与后退、主题切换后滚动与激活项保留、无脚本最小静态说明、图片或音频加载失败时的局部降级。至少在 1440、1024、768、390、320 px 宽和常见移动高度检查布局，并在 200% 缩放和真机触屏复核关键路径。普通字 4.5:1、大字 3:1 是 WCAG AA 目标；移动 LCP ≤ 2.5 秒、CLS ≤ 0.1、INP ≤ 200 毫秒是性能目标，须在明确的设备与网络条件下实测。INP 的真实用户结论需要现场数据，不能用 Lighthouse 单次跑分替代。未提供正式内容与资源前，验收仅能确认结构和交互，不能宣称发布准备完成。

测试文件建议为 `tests/unit/theme.test.ts`、`tests/unit/content.test.ts`、`tests/unit/gallery.test.ts` 和 `tests/e2e/home.spec.ts`。单测验证纯规则，存储抛错、系统事件、焦点及媒体行为通过浏览器测试验证。端到端配置显式启动构建预览服务器。每个主要交互先定义预期失败场景，再实现相应行为；单测初始设置 60 秒进程时限，超时实际终止进程并报告，不把工具等待超时误当作进程已结束。
